# Sunny Narrator

[English](README.md) | **Русский** | [中文](README_CN.md) | [Português](README_PT.md) | [Türkçe](README_TR.md)

**Версия:** 2.9  
**AI-переводчик книг с глоссарием (AI book translator)** для форматов FB2/TXT/EPUB/DOCX/PDF — переводчик художественной литературы на базе LLM (LLM fiction book translator) с двумя независимыми LLM и 5-стадийным контролем качества.

🖥️ **Консольная утилита (CLI)** — без графического интерфейса, требует базового опыта работы с командной строкой.

**Предназначен для:**
- 📚 Перевода серий книг по глоссарию (единая терминология во всех томах)
- 🔨 Создания словарей для переводов книг и серий
- 💻 Локальных GPU (16-24 ГБ VRAM) через llama.cpp, Ollama, LM Studio и т.п., а также любой OpenAI-совместимый API (3-4 млн токенов на книгу)
- ☁️ Онлайн-сервисов перевода через API
- 🎓 Профессиональных и не только переводчиков — для формирования драфта перевода книги и словарей

## 🔄 Общий workflow

### Поддерживаемые форматы

| Входной формат | Пайплайн |
|----------------|----------|
| **FB2, TXT** | Классический пайплайн (прямая работа с XML — сохраняет структуру poem/stanza/v) |
| **DOCX, EPUB, PDF** | Calibre-пайплайн (через промежуточный HTMLZ) |

Пайплайн выбирается автоматически по расширению файла — флаг `--pipeline` не нужен.

```mermaid
flowchart LR
    A[1. Скачать репо] --> B[2. Установить зависимости]
    B --> C[3. Настроить .env]
    C --> D[4. Указать книгу в FILE]
    D --> E[5. python app.py → book.dic]
    E --> F[6. Проверить/очистить словарь]
    F --> G[7. python app.py → перевод]
    G --> H[8. Вычитать книгу]
```

**Пошаговый workflow:**
1. **Скачайте репозиторий** — `git clone` проекта
2. **Установите зависимости** — `pip install -e .` (используется `pyproject.toml`); для DOCX/EPUB/PDF дополнительно нужны `pandoc` и `calibre`
3. **Настройте** — создайте `.env` из `env.sample`, заполните ключи API и `SOURCE_LANG`/`TARGET_LANG`
4. **Выберите книгу** — `FILE=path/to/book.fb2` (или `.txt`, `.epub`, `.docx`, `.pdf`)
5. **Создайте словарь** — `python app.py` создаёт `book.dic` рядом с книгой (spaCy-модель исходного языка скачивается автоматически). Запуск на этом останавливается для проверки словаря (для всех форматов)
6. **Отредактируйте словарь** — проверьте и очистите `book.dic` (удалите ошибки, исправьте переводы, укажите пол)
7. **Переведите** — снова запустите `python app.py`; результат кладётся рядом с исходным файлом, с языковым маркером в имени
8. **Прочитайте и вычитайте** — финальная проверка переведённой книги

## 📋 Конфигурация

Скопируйте прилагаемый `env.sample` в `.env`. Это полная рабочая конфигурация: **Gemma 4** переводит, **Qwen 3.6** вычитывает, обе модели — через OpenAI-совместимый сервер (llama.cpp, Ollama, LM Studio, vLLM или облачный API). Каждая опция описана прямо в файле, а в его конце есть готовые варианты: два сервера llama.cpp, один сервер Ollama, английский оригинал, FB2 → EPUB и быстрый черновик.

```bash
cp env.sample .env
```

Затем поправьте как минимум эти ключи:

```bash
# Translate LLM — Gemma 4

# Книга и языки

SOURCE_LANG=ko

# Вывод: fb2 или epub для FB2/TXT; epub, docx или pdf для EPUB/DOCX/PDF
OUTPUT_FORMAT=fb2
```

## ⚡ Режим FAST_TRANS

**Используйте `FAST_TRANS=true` (или `--fast-mode`) для:**
- ✅ Чернового перевода
- ✅ Технической документации
- ❌ НЕ для финальных публикаций и художественного перевода

**Скорость:** ~2.5x быстрее (2 стадии вместо 5)

**💡 Приём — хороший словарь после первого быстрого прогона:** запустите быстрый перевод с `DICT_AUTO_SAVE=true`. Стадия синопсиса работает и в быстром режиме, поэтому новые имена и термины дописываются в `.dic` (только те, которых словарь ещё не покрывает; у существующей записи может заполниться пустой пол). Проверьте и поправьте словарь, затем переведите книгу второй раз с `FAST_TRANS=false` и `--fresh` — получится качественный перевод с единой терминологией. `--fresh` не даст вернуться чанкам и терминам прерванного быстрого прогона. Работает для всех форматов (FB2/TXT и DOCX/EPUB/PDF).

**Подробности:** [docs/FAST_TRANS.md](docs/FAST_TRANS.md)

## 📏 Калибровка длины чанков

После перевода каждого чанка его длина проверяется относительно ожидаемого соотношения source→target, чтобы отловить обрезанный или раздутый перевод. Вместо фиксированного порога соотношение калибруется автоматически по каждой книге: первые 3 принятых чанка проверяются только на грубые сбои (×0,25 … ×5), после чего ожидаемым соотношением становится медиана по уже принятым чанкам.

**Подробности:** [docs/RECHUNKING_GUIDE.md](docs/RECHUNKING_GUIDE.md)

## 📎 Словарь

Файл словаря (`*.dic`) обеспечивает единую терминологию:

```dic
# Формат: source = target, category, gender, notes
Alice = Алиса, PERSON, she, Главный персонаж
```

- **Создаётся автоматически** при первом запуске (или по `--build-dict`): имена находит spaCy-модель исходного языка, категорию и пол определяет сама книга (большинство меток NER, местоимения, обращения вроде *Miss*/*Mr.*), LLM только переводит. Неуверенный пол остаётся пустым, и запуск останавливается, чтобы вы проверили новый `.dic`. Частотные обычные слова добавляются только при `DICT_FREQUENT_WORDS=true` (или `--frequent-words` для `--build-dict`/`--build-series-dict`).
- **Проверяется по книге перед каждым переводом** (без LLM): уверенные находки — пустой пол, пол или категория, которым книга противоречит, — применяются только к этому запуску; `.dic` не меняется, их получает `<dic>.reviewed.dic`. `--no-autofix` останавливает запуск при противоречии, `--force` переводит всё равно; отчёт — `<книга>.dictcheck.txt`.
- **Пол персонажей** (`he`, `she`, `it`, `they`): все стадии получают его в форме языка перевода (`Вашти — она (сказала)`), стадия GENDER исправляет предложения, которые противоречат словарю. Пол в файле запуск никогда не перезаписывает; синопсис заполняет только пустой, когда согласны два чанка.
- **Выдуманные слова:** кроме персонажей стадия синопсиса сообщает о выдуманных словах без обычного перевода (`spidergun`); они добавляются как `TERM`. Слова, которые знает модель spaCy, отбрасываются.
- **Без дублей:** кандидат, который словарь уже покрывает, не добавляется — другой регистр или словоформа записи (`Jain nodes` = `Jain node`, `Gabbleducks` = `gabbleduck`; имя — только словоформа: `Jains` = `Jain`, но `Marie` ≠ `Mary`) или фраза с известным термином (`Jain node`, `Jain-tech` при `Jain`). Дефис, пробел и слитное написание — разные записи (`gabble-duck` ≠ `gabbleduck`); аббревиатура капсом совпадает только сама с собой (`ECS` ≠ `EC`).
- **Куда попадает найденное:** новые имена и термины сразу входят в словарь в памяти — их получают следующие чанки запуска, а продолженный запуск восстанавливает их из чекпоинта. В `.dic` они пишутся только при `DICT_AUTO_SAVE=true` (по умолчанию `false`: проверенный словарь остаётся как есть).
- **Поиск терминов:** одинаковый для всех форматов — в промпт чанка попадают только найденные в нём термины словаря. Находятся словоформы (`spidergun` → `spiderguns`, `паукопушка` → `паукопушками`), термины на китайском/японском/корейском ищутся подстрокой, а внутри другого слова термин не находится (`Ann` / `Annoying`).
- **Многословные термины в приоритете:** термин из большего числа слов важнее более коротких, которые в него входят (`Mad Hatter` вместо `Hatter`), затем побеждает более длинный. Короткий термин, встречающийся только внутри длинного, в промпт не попадает — модель не получает два перевода одной фразы.
- **Подстановка терминов перед переводом:** переводы найденных в чанке терминов подставляются в исходный текст перед первой стадией, чтобы модель их не пропускала (следующие стадии видят оригинал). Разметка, ссылки и URL не затрагиваются; термин в нижнем регистре находится в любом регистре, имя — как написано или КАПСОМ.
- **Другой язык перевода:** `python app.py dict convert books/MyBook.dic fr es zh` конвертирует готовый словарь в другие языки (`MyBook_fr.dic`, …), используя существующий перевод как подсказку.
- **Явный путь к словарю:** по умолчанию словарь ищется рядом с книгой (`books/MyBook.fb2` → `books/MyBook.dic`). Чтобы использовать другой файл, например общий словарь серии, задайте `DICTIONARY=path/to/file.dic` в `.env` или передайте `--dictionary path/to/file.dic` (флаг CLI приоритетнее). Работает в обоих пайплайнах; отсутствующий файл создаётся по этому пути (каталог должен существовать).

**Формат:** [docs/DICTIONARY_FORMAT.md](docs/DICTIONARY_FORMAT.md)

### Работа со словарём

| Задача | Команда / шаг |
|---|---|
| Новая книга без словаря | `python app.py` (или `python app.py --build-dict books/MyBook.epub`) → `books/MyBook.dic` + `books/MyBook.dictcheck.txt` → заполните известные вам пустые полы → запустите снова |
| Перевод со словарём | `python app.py` — сначала проверка; прочитайте `<книга>.dictcheck.txt`, при согласии возьмите `<dic>.reviewed.dic` |
| Строгий режим | `python app.py --no-autofix` — остановка при противоречии (код 2); `--force` — переводить всё равно |
| Серия книг | `python app.py --build-series-dict books/series/ --series-dict-output series.dic`, затем каждая книга с `--dictionary series.dic`; запуск никогда не меняет `series.dic`, каждая книга получает `series.<книга>.reviewed.dic` |
| Почистить словарь | `python app.py dict clean books/MyBook.dic` → `MyBook.clean.dic` + отчёт (дубли, написание пола, обычные слова) |
| Проверить по книге без перевода | `python app.py dict review books/MyBook.epub --dic books/MyBook.dic` → `MyBook.reviewed.dic` + отчёт |
| Другой язык перевода | `python app.py dict convert books/MyBook.dic fr es zh` |
| Проверить готовый перевод | `python app.py audit books/MyBook_ru.epub --dic books/MyBook_ru.dic --lang russian` |

**Языки.** Словарь строится и проверяется spaCy-моделью **исходного** языка (`NERMODEL`, выбирается по `SOURCE_LANG`): `python -m spacy download en_core_web_lg` (английский), `ru_core_news_lg`, `de_core_news_lg`, `fr_core_news_lg`, `es_core_news_lg`, `it_core_news_lg`, `pt_core_news_lg`, `pl_core_news_lg`, `uk_core_news_lg`, `ko_core_news_lg`, `ja_core_news_lg`, `zh_core_web_lg`; для остальных языков — `xx_ent_wiki_sm` (только имена, без пола по местоимениям). Для проверки пола в **переводе** нужна модель языка перевода (`ru_core_news_sm`, `pl_core_news_sm`, `fr_core_news_sm`, …). Род местоимений китайского, японского и корейского определяется по написанию; книга на языке без родовых местоимений (турецкий, финский, венгерский) пола не даёт — укажите его вручную.

### Перед переводом (или повторным переводом) серии

1. Сохраните копию словаря: `cp series.dic series.dic.bak`.
2. Почистите: `python app.py dict clean series.dic` — прочитайте отчёт, перенесите согласное.
3. Сверьте с каждой книгой, каждую в свой файл: `python app.py dict review book1.epub --dic series.dic -o series.book1.reviewed.dic` (так же для book2, …). Перенесите то, в чём книги согласны; остальное решите вручную — в первую очередь разделы `gender conflict` и `gender not sure`.
4. Вручную исправьте то, что не решит ни один инструмент: персонаж-женщина, чьё имя в языке перевода — существительное мужского рода (`Client` → `Клиентка`?), вид или должность с категорией PERSON (→ `TERM`), пол, который «прыгает» между `it`/`he`/`they`.
5. Переводите книги по порядку серии с `DICTIONARY=series.dic`, `DICT_AUTO_SAVE=false`, `--fresh`. Перед первым чанком словарь проверяется по этой книге; уверенные исправления действуют только на этот запуск.
6. После каждой книги, до следующей: прочитайте отчёт запуска (*The translation disagrees with the dictionary*, *Genders filled in from the synopsis*, *Words in two alphabets*), `<книга>.dictcheck.txt` и `series.<книга>.reviewed.dic` и перенесите верное в `series.dic`. Сравните со старым переводом: `python app.py audit … --compare …`.

## 🈶 CJK-языки (корейский, японский, китайский)

Книги можно переводить с CJK-языков напрямую на любой язык, со словарём:

- **NER:** `ko_core_news_lg` использует собственную схему меток KLUE (`PS`/`LC`/`OG`) — она распознаётся и приводится к `PERSON`/`LOC`/`ORG`.
- **Поиск по словарю:** CJK-термины ищутся подстрокой — пробелов между словами нет, а корейские частицы пишутся слитно с существительным (`철수는`).
- **Модели:** `python -m spacy download ko_core_news_lg` (ничего дополнительного); `ja_core_news_lg` и `zh_core_web_lg` требуют токенизаторы: `pip install -e ".[cjk]"`.
- **Корейские частицы:** сущности попадают в словарь без приклеенной частицы (`철수는` → `철수`, `서울에서` → `서울`), поэтому термин находит все формы слова. Из-за поиска подстрокой короткое имя находится и внутри более длинного (`철수` в `김철수`) — такие термины стоит проверить в созданном `.dic`.
- **Приоритет:** побеждает самый длинный термин (`魔王城` над `魔王`); латинский термин внутри CJK-текста (`ABC社`, в том числе полноширинный `ＡＢＣ`) подставляется как отдельное слово.
- **Частотные слова** (только при `DICT_FREQUENT_WORDS=true`): минимальная длина слова — 2 символа вместо 5 (CJK-слово обычно занимает 1-3 символа).
- **Контроль длины:** при переводе на алфавитные языки CJK-текст вырастает в 2-4 раза по символам. Ожидаемое соотношение вычисляется по самой книге — медиана принятых чанков; первые 3 чанка проверяются только на грубые сбои (×0,25 … ×5).

```bash
SOURCE_LANG=korean
TARGET_LANG=russian
```

## 🌍 Проверенные языки

Целевым может быть любой язык, на котором пишет LLM; код словаря учитывает язык. Проверено:

| | Языки |
|---|---|
| **Реальные переводы книг** | английский → русский, корейский → русский |
| **Исходный, на реальной модели spaCy** (NER, словоформы терминов, очистка артиклей/частиц) | английский, корейский, японский, китайский, русский, немецкий, французский, испанский, португальский, итальянский |
| **Исходный, с ограничениями** | турецкий (многоязычный NER; термин находится только в той форме, что записана в `.dic`) |
| **Целевой, автотесты** | русский, турецкий (все пять стадий с имитацией LLM), немецкий, китайский |

**Подробности и ограничения:** [docs/LANGUAGES.md](docs/LANGUAGES.md)

## 📖 Перевод по глоссарию (серия книг)

Создайте единый глоссарий для серии книг, чтобы терминология совпадала во всех томах.

### Построение глоссария серии

```bash
# Базовое использование
python app.py --build-series-dict books/ --series-dict-output series.dic

# С пользовательскими порогами
python app.py --build-series-dict books/ --series-dict-output series.dic --min-count-ner 3 --frequent-words --min-count-word 5
```

**Параметры:**
- `--build-series-dict` — путь к папке с книгами FB2/EPUB/TXT
- `--series-dict-output` — выходной файл словаря (по умолчанию: `series.dic`)
- `--min-count-ner` — минимальное число упоминаний для NER-сущностей (по умолчанию: 2)
- `--frequent-words` — добавить и частотные обычные слова, а не только именованные сущности (по умолчанию выключено, `DICT_FREQUENT_WORDS`)
- `--min-count-word` — минимальное число упоминаний для частотных слов при `--frequent-words` (по умолчанию: 5)

Словарь для одной книги строится командой `--build-dict path/to/book`.

**Workflow:**
1. Найти все файлы книг в папке
2. Извлечь текст из каждой книги
3. Запустить NER: одна запись на сущность (формы по лемме, категория по большинству упоминаний)
4. Сложить количества по всем книгам
5. Отфильтровать по порогам
6. Перевести термины через proofread-LLM (она только переводит; пол ставит проверка перед переводом каждой книги)
7. Сохранить единый `.dic` файл

**Результат:** обычный `.dic` файл (`source = target, category, gender, notes`). Имена собственные сохраняют заглавные буквы и все слова (`John Smith`).

## 💾 Возобновление после сбоя

Прогресс автоматически сохраняется после каждого чанка:

```bash
# Прервано на 50%
python app.py  # Ctrl+C

# Автоматическое возобновление
python app.py  # ✓ Продолжено с чанка 51/100
```

Флаг `--fresh` игнорирует чекпоинт и начинает перевод заново (оба пайплайна).

## 🔄 Calibre-пайплайн (DOCX/EPUB/PDF)

Принимает **DOCX/EPUB/PDF** напрямую — без ручной конвертации.
Пайплайн выбирается автоматически для файлов с расширением `.docx`, `.epub` или `.pdf`.

```bash
# Установить системные зависимости
sudo apt install pandoc calibre
pip install -e .

# Перевести DOCX/EPUB/PDF (автоопределение по расширению)
FILE=books/mybook.epub python app.py --output-format epub
```

**Пайплайн:** DOCX/EPUB/PDF → Calibre → HTML → Markdown → Перевод → HTML → Calibre → DOCX/EPUB/PDF

Служебная разметка Calibre (якоря `calibre_link-*`, классы `.calibre`) удаляется автоматически, а оглавление строится заново по переведённым заголовкам.

> ⚠️ **FB2 не поддерживается Calibre-пайплайном.** У FB2 богатая структура
> (poem/stanza/v), которую промежуточный HTMLZ сплющивает в обычные абзацы —
> потеря качества необратима. Для FB2 используется **классический пайплайн**
> (по умолчанию для `.fb2` и `.txt`): он работает с XML напрямую и сохраняет
> всю структуру книги.

**FB2 → EPUB:** `FILE=books/mybook.fb2 python app.py --output-format epub` (или `OUTPUT_FORMAT=epub` в `.env`). Классический пайплайн переводит FB2 и собирает EPUB прямо из него: вложенное оглавление, сноски, обложка, картинки, стихи и эпиграфы.

**Полное руководство:** [docs/INSTALLATION.md](docs/INSTALLATION.md#-calibre-pipeline-auto-detected)

## 📜 Логирование

В консольном логе видны все шаги перевода: проверки длины с откалиброванным соотношением, запись пола в словарь, найденные в чанке словарные термины, чекпоинты.

![Консольный лог перевода с корейского на русский](logging.png)

- `DEBUG=on` — подробный лог (проверки длины, сопоставление словаря, синопсис)
- `DEBUG_HTTP=on` — дополнительно сырые HTTP-трассы LLM-клиентов
- `LLM_LOGGING=true` — каждый вызов LLM (промпты, ответ, токены, время) в виде JSON-строк в `logs/llm_calls_YYYY-MM-DD.log` (каталог: `LLM_LOGGING_DIR`)

**Подробности:** [docs/LOGGING.md](docs/LOGGING.md)
